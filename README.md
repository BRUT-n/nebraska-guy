> Рекурсивный сканер зависимостей, который находит уязвимых, уставших мейнтейнеров, на которых держится ваш продакшн. Вдохновлено комиксом [xkcd 2347](https://xkcd.com/2347/).

## Что он делает

Укажите проекту на пакет или GitHub-репозиторий — он пройдёт по всему дереву зависимостей до самого низа, рассчитает **bus factor** (фактор автобуса) и **fragility score** (индекс уязвимости) для каждого узла. Затем LLM напишет драматичный отчет о том, на чём на самом деле стоит ваш продакшн.

Название происходит из известного комикса xkcd: *"вся современная цифровая инфраструктура — это проект, который какой-то случайный человек из Небраски неблагодарно поддерживает с 2003 года"*. Этот инструмент находит того самого человека.

## Как это работает

1. Вы отправляете корневой пакет (например, `requests`).
2. API ставит задачу на фоновое сканирование в очередь и мгновенно возвращает ответ.
3. Воркеры рекурсивно обходят дерево зависимостей, кэшируя результаты и учитывая ограничения на количество запросов (rate limits) со стороны GitHub/PyPI.
4. Каждый проанализированный узел генерирует событие, которое в реальном времени стримится в браузер.
5. По завершении обхода система рассчитывает метрики уязвимости и запрашивает отчёт у LLM.

## Технологический стек

- **Python 3.12** — основной язык
- **FastAPI** — HTTP API
- **Pydantic** — валидация запросов и ответов
- **Piccolo ORM** — модели базы данных
- **PostgreSQL** — хранение данных (персистентность)
- **Neo4j** — графовая база данных для связей и визуализации дерева
- **Redis** — кэш и ограничение частоты запросов (rate limiting)
- **Celery** — фоновые воркеры
- **Kafka** — шина событий для обновлений в реальном времени
- **WebSocket** — живой рендеринг дерева в браузере
- **Ruff** — линтер и форматитер кода
- **pre-commit** — автоматические проверки кода перед каждым коммитом

## С чего начать

Выполните следующие команды в терминале:

1. **Настройте переменные окружения:**
   Создайте локальный файл конфигурации на основе примера:
   ```bash
   cp .env.example .env
   ```
   *(При необходимости откройте файл `.env` и отредактируйте стандартные пароли)*

2. **Запустите базы данных:**
   Разверните контейнеры PostgreSQL и Neo4j в фоновом режиме:
   ```bash
   docker compose up -d
   ```
    *(Требуется Docker и Docker Compose)*

3. **Проверьте статус контейнеров:**
   Убедитесь, что все сервисы успешно запустились и прошли хелсчеки:
   ```bash
   docker compose ps
   ```

   После успешного запуска локальное окружение доступно по следующим адресам:
   **PostgreSQL** | `localhost:5432` | Реляционная БД (основное хранилище сканов) 
   **Neo4j Browser** | `http://localhost:7474` | Веб-интерфейс графовой БД для ручных запросов
   **Neo4j Bolt** | `localhost:7687` | Сетевой порт для подключения Python-драйвера
